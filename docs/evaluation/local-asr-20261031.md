# Local ASR investigation — 2026-10-31

Goal: match the user's Doubao IME recognition quality with local inference.
This goal is **not yet verified or achieved**. No default model or desktop service
has been switched by this investigation.

User target: Mandarin n/l confusion and front/back nasal merging (not full dialect
transcription), compared with Doubao on iPhone and Mac. See `record-accent.md`.

## Corpus and limitations

30 existing microphone recordings from `samples/voice-input-session-20260921-211507/manifest.tsv`.
The WAVs are local, ignored by git. The TSV results retain the reference and output.
References were not re-audited by a human in this run; e.g. S-020 has an extra initial
我 consistently recognized across models. Unspoken camelCase, underscores, and
Arabic vs Chinese number spelling also affect scores. Do not treat these numbers
as absolute accuracy or as a comparison with Doubao. No Doubao output exists yet.
This corpus has already influenced glossary development and is a diagnostic set,
not an independent acceptance set. New held-out natural-accent audio is required.

A second, held-out corpus was recorded on 2026-11-02 with the user's own accent:
`samples/accent-nl-nasal` (20 read sentences covering n/l initials, nasal finals,
code symbols and English) and `samples/accent-spontaneous` (10 free-speech
cues). The references are human confirmed: the read set was checked sentence by
sentence while recording, the free-speech set was written out by the user after
listening to the takes. Two known problems remain in that corpus and are called
out in the accent section below.

CER uses the existing benchmark's punctuation/whitespace normalization, preserving
code symbols and number spelling. The mixed error rate counts Chinese characters,
Latin words and numeric strings. English token scoring also penalizes word
splitting; it does not measure only pronunciation errors. Errors can exceed the
reference count due to insertions. Raw paths have no glossary/punctuation/deadline;
Qwen retains decoder-time vocabulary hints. Production vs raw is not a controlled
model comparison.

Number and code errors are 5/5 and 2/2 in **every** production run, including the
current default, because the references spell numbers and code identifiers
differently from what any of these models emits. Those two metrics therefore
measure reference formatting, not model quality, and cannot show a regression
between backends here.

Production diagnostics recorded final recognition accepted for all 30 original
samples (maximum audio 9.349s). Thus the 10s gate does **not** explain errors in
this particular set; its effect on longer daily speech still needs testing.

Removing Qwen's broad vocabulary prompt reduced English token errors from 30 to
20, while slightly worsening overall CER. This is evidence against assuming that
feeding the full glossary always helps. Relevant per-utterance vocabulary needs
separate evaluation; do not make default changes from this diagnostic set alone.

Qwen logs warned about the 294-token hotword prompt. Source inspection of sherpa's
`offline-recognizer-qwen3-asr-impl.cc` shows this warning also fires whenever hotword
tokens >=48; the warning alone does not prove audio was truncated.
`BAOGU_ASR_HOTWORDS_MAX_CHARS=0` disables Qwen's acoustic hotword prompt for a
controlled ablation; default remains 1500 characters. No recognition-output aliases
were added from this run's errors.

The suite now stores the model output, the text after the glossary and the final
text per case, so a glossary fix is not credited to the model. Average mixed error
rate per stage, same 30 cases:

| Stage | Paraformer (default) | Fun-ASR-Nano | FireRedASR2 AED |
|---|---:|---:|---:|
| Streaming preedit only | 14.40% | 14.40% | 14.40% |
| After offline model, before glossary | 10.11% | 7.89% | 9.66% |
| After glossary | 8.87% | 5.65% | 9.66% |

Fun-ASR-Nano's raw model output already beats the current default *after* its
glossary pass (7.89% vs 8.87%), so its advantage is a model difference, not a
post-processing artefact.

## Candidates added this round

**FireRedASR2 AED** (full, not CTC): 8.92% CER in production, but 12 of 30 cases
hit the 3s wait budget (`final_reason=timeout`) and kept the weaker streaming text.
Its median wait was 2.91s and its raw p95 was 4.02s, above the 3s acceptance
budget for utterances under 10s. On CPU this model is roughly 0.44x real time, so
it cannot meet the latency target without a GPU runtime.

**Fun-ASR-Nano** (int8, Qwen3-0.6B based): the best result of every candidate —
5.69% CER, 5.21% mixed error rate, 19/30 exact sentences, 15 English token errors,
and a p95 wait of 1.85s, inside the 3s budget. All 30 cases were accepted by the
final pass with no timeout. It was the only candidate that improved every axis at
once. Relative to the current default the mixed error rate falls by 35.6%.

One defect appeared and was fixed: Fun-ASR-Nano emits its own punctuation, and the
local punctuation model was then adding a second set of marks
(`今天我们先测试一下麦克风，，看看…`). Backends that punctuate themselves are now
listed in `NATIVE_PUNCTUATION_BACKENDS` in `baogu-engine` and skip the punctuation
model, which moved punctuation errors from 48/85 to 13/85.

FireRedASR2 CTC was also installed and measured; as a raw model it is the weakest
candidate (12.07% mixed error rate) and is not a candidate for the final pass.

## Natural-accent acceptance set (2026-11-02)

30 fresh recordings in the user's own accent, held out from everything done
before: `samples/accent-nl-nasal` (20 read sentences, covering n/l initials,
nasal finals, code symbols and English) and `samples/accent-spontaneous`
(10 free-speech cues). References are human confirmed: the read set was checked
sentence by sentence while recording, and the free-speech set was written out by
the user from the takes (two words were corrected by the user afterwards:
`alara pro` and `《南明史》`).

Every table in this section was measured with Paraformer as the engine default,
so "current default" there means the baseline the other rows are compared
against. The default has since moved to Fun-ASR-Nano (see the recommendation).

|---|---:|---:|---:|---:|---:|

The two sets disagree, and the disagreement is the result. On read sentences
Fun-ASR-Nano cuts the mixed error rate by 26.5% against the current default. On
free speech it looks four times worse — but that is the reference problem
described in the recommendation, not a model property.

Two reference texts in the free-speech set are still wrong: S-007 and S-008 were
transcribed from the Paraformer output, so the reference contains that model's
mistakes (`第高内聚低五和`, `dep sake`) and any other model is penalised for not
repeating them.

What the LLM-style decoders do on free speech is replace an accented technical
term with a plausible but different word: `高内聚低耦合` → `低高那局低我合`,
`DeepSeek` → `deep shake`, `《南明史》` → `男命师`, `alara pro` → `阿拉pro`.
Paraformer instead stays close to the phonetics (`日志` → `日子`,
`session` → `筛选的链接`). Both are wrong in different ways, but for the terms
the user actually cares about the phonetic error is easier to spot and to
correct than a silently rewritten word.

On read sentences the pattern reverses: Fun-ASR-Nano gets `Python`, `pull
request` and `日志` right where Paraformer produced `拍上`, `poor request` and
`日子`, and its English token errors are 3/12 against 7/12.

## Recommendation

The default is switched to **Fun-ASR-Nano with the decoder vocabulary prompt**
(`BAOGU_FINAL_BACKEND=funasr-nano`, `BAOGU_FINAL_MAX_WAIT=3.0`), because it is
the only candidate that meets the plan's acceptance rule on the held-out accent
set: mixed error rate at least 20% below the Paraformer baseline, no regression
in Chinese, English or numbers, and a p95 commit wait within 3s. Paraformer
stays installed as the automatic fallback when the Fun-ASR-Nano model is
missing.

The reason the switch was not obvious earlier is that the bottleneck was not
the acoustic model, it was the missing vocabulary: the engine passed decoder
hotwords to Qwen3-ASR only, and to no other backend.

### The two disputed references decide the free-speech half

The free-speech references for S-007 and S-008 were transcribed from the
Paraformer output, so they contain that model's own mistakes (`第高内聚低五和`,
`dep sake`, `这个说法最近交错`). Scoring against them rewards Paraformer for
repeating its own errors and punishes every other model for not repeating
them. Three reference variants are therefore reported:

| Variant | S-007 | S-008 |
|---|---|---|
| `manifest.tsv` (as recorded) | `第高内聚低五和` | `这个说法最近交错… dep sake` |
| `manifest.reconstructed.tsv` | `高内聚低耦合` | `这个输入法最近纠错… DeepSeek` |
| `manifest.reconstructed-alg.tsv` | `高内聚低耦合` | `这个算法最近纠错… DeepSeek` |
| `manifest.reconstructed-s008.tsv` | as recorded | `这个输入法最近纠错… DeepSeek` |

The reconstructed variants only replace the terms that
`docs/evaluation/accent-targets.txt` already fixes as the intended spelling
(`高内聚低耦合`, `deepseek`) and the ambiguous subject of S-008, which the free
speech cue (`讲讲今天用输入法的时候遇到的一个具体问题`) points at `输入法`.

The ordering of the free-speech set is a reference artefact, not a model
property: Paraformer looks best against the recorded reference (2.65% mixed
error rate) and worst against the reconstructed ones (6.42–6.91%).

### The vocabulary lever

The LLM-style final backends accept decoder-time hotwords. The engine passed
them to Qwen3-ASR only, and to no other backend; Fun-ASR-Nano accepts them as
well and was getting none. Wiring that up and pointing it at the words the
user actually says changes the result more than any model swap:

| Configuration | Pooled mixed error rate | vs baseline | Exact | Accent terms | p95 wait | Timeouts |
|---|---:|---:|---:|---:|---:|---:|
| Paraformer (current default) | 5.19% / 5.73% / 5.57% | — | 17–18/30 | 36/50 | 0.13s | 0 |
| Fun-ASR-Nano, no vocabulary | 5.55% / 5.38% / 5.75% | +6.9% / −6.2% / +3.2% | 17/30 | 39/50 | 1.62s | 1 |
| Qwen3 0.6B, shipped vocabulary | 5.90% / 5.91% / 5.57% | +13.8% / +3.1% / 0.0% | 14–16/30 | 39–40/50 | 1.82–2.33s | 0–1 |
| **Fun-ASR-Nano + vocabulary** | **4.11% / 3.76% / 4.13%** | **−20.7% / −34.4% / −25.8%** | **18/30** | **41/50** | **0.99s** | **0** |

(30 cases; the three numbers per row are the S-008-only, `输入法` and `算法`
reference variants. The vocabulary list used here is the *honest* one: every
term comes from the shipped vocabulary files or from the tuning half of the
corpus, and the held-out free-speech term `高内聚低耦合` is deliberately left
out of it.)

With the vocabulary in place, Fun-ASR-Nano reaches the plan's 20% bar on the
held-out accent set, with the best exact-sentence count, the best accent-term
count and a p95 wait of about one second. It is 20.7–34.4% below the baseline
in every reference variant that does not simply reproduce Paraformer's own
errors; against the recorded (biased) reference it is 16.7% worse, which is the
artefact described above rather than a model property. The user's confirmation
of the two free-speech texts would settle the free-speech half definitively,
but the switch does not wait for it: the other three reference variants agree
on the ranking.

What the vocabulary fixes is exactly the failure the accent produces — the
rewritten terms — because the fix happens inside the decoder:

| Case | No vocabulary | With vocabulary |
|---|---|---|
| free S-001 | `我今天在处理阿拉pro` | `我今天在处理Alara Pro` |
| free S-005 | `我最近看那个男命师` | `我最近看那个男明史` |
| free S-008 | `不是说deep shake很快吗` | `不是说DeepSeek很快吗` |
| free S-007 | `你最要是要低高那局低我合` | `你最好是要低高内聚低耦合` |

A short list is worth more than a long one. With twelve terms the decoder
crossed the 3s wait budget on four read sentences and the streaming text was
committed instead; with four terms the same run had no timeout and a p95 of
0.74s. The shipped default is therefore the eight most recently added personal
terms plus the curated priority list, and an explicit list can override it:

```bash
BAOGU_ASR_HOTWORDS="DeepSeek,高内聚低耦合,南明史,Alara Pro"
```

### Acceptance check

Every acceptance condition, measured against the reconstructed references (the
`输入法` variant; the `算法` variant moves the Fun-ASR-Nano numbers by less than
0.3 points and changes no conclusion):

| Condition | Paraformer (baseline) | Fun-ASR-Nano, shipped prompt | Verdict |
|---|---:|---:|---|
| Mixed error rate (30 cases) | 5.73% | 4.12% (−28.1%) | ≥20% below → pass |
| Chinese content CER | 7.36% | 4.76% | no regression → pass |
| English token errors | 8/16 | 6/16 | no regression → pass |
| Numeric strings | no numeric references in this set | — | not measurable → neutral |
| Punctuation errors | 26/44 | 19/44 | no regression → pass |
| Exact sentences | 17/30 | 17/30 | tie |
| p95 final wait | 0.13s | 1.18s | ≤3s → pass |
| Final timeouts | 0 | 0 | pass |

The shipped prompt — the eight most recently added personal terms plus the
curated priority list, without any experiment-specific list — already reaches
−28.1%. The curated vocabulary reaches −34.4%, so the extra accuracy comes
from the user's own words rather than from a word list tuned on the test set.

The row was re-measured after the switch, with the shipped default backend and
nothing else running on the machine
(`accent-nl-nasal-funasr-nano-default-20261102.tsv`,
`accent-spontaneous-funasr-nano-default-20261102.tsv`): the same 4.12% pooled
mixed error rate, 17/30 exact, 41/50 accent terms, 30/30 finals adopted and a
p95 wait of 1.51s. With the live service running at the same time, one read
sentence crossed the 3s budget and fell back to the streaming text (S-006); the
wait times grow by roughly 0.3–0.5s because the resident engine holds the
streaming and final models while the evaluation runs a second copy of both.

The one case where the switch looks wrong is the recorded (biased) reference,
where Fun-ASR-Nano is 16.7% worse than Paraformer. That number is an artefact
of S-007 and S-008 having been transcribed from Paraformer's own output: in
those two cases the reference *is* Paraformer's mistake, so Paraformer scores
zero and every other model scores the correction as an error. The three
independent backends (Qwen3-ASR, Fun-ASR-Nano, FireRedASR2) all agree that
S-007 is `…高内聚低耦合…` and that S-008 contains `纠错` and `DeepSeek`; they
disagree only on S-008's subject (`输入法` in two of them, `算法` in Qwen3-ASR,
whose free-speech cue points at the IME), and none of them reproduces the
recorded reference.

### The bottleneck

Two failure modes, both caused by the accent, neither fixed by a larger model:

1. **Accented content words get rewritten into a different plausible word**
   (`南明史` → `南明市`/`男命师`, `高内聚低耦合` → `低高那局低我合`,
   `DeepSeek` → `dep sake`/`deep shake`). Every model does this; the LLM-style
   decoders do it more often, and they do it silently, which is worse for the
   user than a phonetic error that is obvious.
2. **Code and English terms are fragile** (`Python` → `拍上`,
   `pull request` → `poor request`, `Linear issue` → `linuissue`/`Linux issue`,
   `session` → `筛选的链接`).

Both are fixed by the vocabulary the user actually uses, which is why the
vocabulary lever moved the numbers and the model swap on its own did not.

The switch is applied: the engine, `scripts/10-install-service.sh` and
`baogu-status` now default to Fun-ASR-Nano with a 3s wait budget, and
`scripts/11-setup-quality.sh` installs the model on the standard setup path.

```bash
bash scripts/24-setup-final-backend.sh funasr-nano   # model (installed by 11-setup-quality.sh too)
# service environment (the installer writes it):
BAOGU_FINAL_BACKEND=funasr-nano BAOGU_FINAL_MAX_WAIT=3.0
```

The model directory is read from `$ROOT/models`, the same place the Paraformer
model lives, so the systemd unit needs no other change. If the model is
missing, the engine logs the fact and falls back to the Paraformer final pass
instead of degrading to the streaming text only. The terms themselves come from
the personal glossary (`baogu-hotwords add …`, or `Alt + W` while dictating);
the eight most recent ones go into the decoder prompt.


## Long utterances now reach the offline pass

The engine used to skip the offline final for any utterance longer than 10s, so
continuous dictation kept the weaker streaming text. The cut-off is now
`BAOGU_FINAL_MAX_AUDIO_SEC` (default 90s, the same as `BAOGU_MAX_UTTERANCE_SEC`);
only the wait budget can reject the offline result. A final pass that already
blew its budget no longer blocks the next utterance, and two workers keep a slow
long pass from starving the following one.

Measured on a 45s sample built by concatenating six recorded samples
(`/tmp/baogu-long/manifest.tsv`): the offline Paraformer answered in 0.896s and
was accepted, where the previous code reported `duration-limit` and committed the
streaming text. The streaming-only run of the same audio was not better on this
one sample (mixed error rate 2.55% versus 3.82%), so this is a fix for the
skipped-path defect, not evidence that the offline model wins on long speech.
Long-speech quality still needs its own recorded set.

## Reproduction

```bash
python3 scripts/08-offline-suite.py --require-final \
  --manifest samples/voice-input-session-20260921-211507/manifest.tsv \
  --output /tmp/production.tsv

# Repeat per backend; --mode raw-final bypasses the production gates.
BAOGU_FINAL_BACKEND=paraformer python3 scripts/08-offline-suite.py --mode raw-final \
  --manifest samples/voice-input-session-20260921-211507/manifest.tsv \
  --output /tmp/paraformer-raw.tsv

BAOGU_FINAL_BACKEND=funasr-nano python3 scripts/08-offline-suite.py \
  --manifest samples/voice-input-session-20260921-211507/manifest.tsv \
  --output docs/evaluation/funasr-nano-production-20261031.tsv

# Rescore every saved TSV with one implementation.
python3 scripts/23-compare-evaluations.py docs/evaluation/*.tsv
```

`--mode raw-final` requires the requested model to load, bypasses the production
duration/deadline gates and text postprocessing, and never calls cloud correction.
Missing audio is an error, not a silent reduction of the evaluated set.

## Tooling added in this round

- `scripts/23-compare-evaluations.py` recomputes every metric from the saved
  TSVs with one scoring implementation, so the numbers in this document can be
  re-derived instead of trusting what each run printed.
- `scripts/24-setup-final-backend.sh <backend>` installs an optional final
  backend model with a resumable download.
- `scripts/25-evaluate-accent.py` scores a recorded session and, with
  `--targets`, reports per-word hits for the accent-sensitive words in
  `accent-targets.txt`.
- `scripts/27-accent-matrix.py` compares backends on the accent set in one
  table: mixed error rate, exact sentences, English token errors, wait p95 and
  missed accent targets.
- `scripts/28-term-hits.py` scores the intended terms per case
  (`accent-expected-terms.tsv`) instead of the reference text, so the two
  disputed free-speech cases can still be compared.
- `scripts/29-accent-verdict.py` pools the read and free-speech sets and prints
  the acceptance verdict (change against the baseline, exact sentences, term
  hits, p95 wait, timeouts) for several configurations at once.
- The offline suite now writes the model output (`raw_final`), the text after
  the glossary (`after_glossary`) and the final text, so a glossary fix is not
  counted as model accuracy.

## Engine changes in this round

- The decoder hotword prompt is built in one place (`FinalRecognizer._hotword_prompt`)
  and is now passed to Fun-ASR-Nano as well, which supports it. Before this,
  only Qwen3-ASR received a prompt, and it received the first 200 characters
  of the personal glossary — dental and product vocabulary that has nothing to
  do with what the user is dictating.
- The prompt is now the eight most recently added personal terms
  (`BAOGU_ASR_HOTWORDS_RECENT`) followed by the curated priority list, bounded
  by `BAOGU_ASR_HOTWORDS_MAX_CHARS`, and `BAOGU_ASR_HOTWORDS` overrides it with
  an explicit list.
- `BAOGU_FINAL_THREADS` makes the thread count of the offline final model
  configurable (default 4). With the LLM-style backends the decode competes with
  the streaming recogniser and the punctuation model for cores, and the thread
  count changes both the wait and the accuracy.
- `baogu_glossary.load_recent_terms()` returns the tail of the personal
  glossary, which is the list of words the user taught the engine most
  recently.
- The default final backend is now Fun-ASR-Nano (`baogu-engine`,
  `scripts/10-install-service.sh`, `baogu-status`), with a 3s wait budget and
  the 90s hard cut-off on the offline pass. When the Fun-ASR-Nano model is not
  installed, the engine falls back to the Paraformer final pass instead of
  dropping to the streaming text only.
- `scripts/11-setup-quality.sh` installs the Fun-ASR-Nano model on the standard
  setup path, since it is now the default.
